Worker 7 re-reviewed `b74404546488e93ba6e5a8bea7fbe83c60396f6f` and confirmed the flexible-array test shape is now valid and the parser remains fail-closed. Run `45346991634` is in progress on the corrected exact head; supply-chain has passed and all three platform jobs are running.

The patch replaces C-string parsing with a strict parser bounded by `CapStr.len`. It rejects embedded NULs, suffix bytes, malformed separators, signs, whitespace, leading zeroes, non-ASCII/non-decimal costs, uppercase/non-hex fields, and any record whose cost is not exactly the current 600,000-iteration generation profile. This is a current-format-only decision pending confirmation that no supported lower-cost legacy records exist; lower-cost records are not silently accepted. `cap_needs_rehash()` now uses the same parser, so a valid-looking prefix cannot be classified as current without validating the entire record. Parsed salt, expected digest and computed digest scratch are wiped.

Regression coverage added to `tests/unit/test_runtime.c`: null arguments, negative record length forged on a valid flexible-array allocation, leading-zero cost, uppercase hex, embedded-NUL suffix, ordinary trailing suffix, non-ASCII cost byte, 600001 first-over-limit cost, and a 100,000,000-iteration record. A test-only PBKDF2 call counter asserts malformed records are rejected before KDF invocation. A structurally canonical current-format record is checked without running the expensive KDF.
