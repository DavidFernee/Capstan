# G1 I06/I07 object and certificate contract candidates
Authority: architecture RFC §§3.6,4,6,10–12; CAP-006; RTM-003/007. Proposed, not frozen; G0 acceptance remains prerequisite. Native/Formal/Security and Integration review required.

## I06 — target stream to executable
Initial target Linux x86-64 SysV, explicit target profile independent of build host. Separate legacy assembly, direct static ELF, and future relocatable-object profiles. Do not infer support for dynamic linking, PIE, TLS, external symbols or managed stack maps from direct scalar ELF.
Input: validated target instruction bytes or bounded encoding intents, declared section layout, symbols, typed fixups, entry, ABI/profile and resource policy. Output: exact immutable executable bytes and canonical mapping from input instruction/relocation identities to byte ranges; or rejection without published executable. No unvalidated raw pointers or ambient imports.
For rel32 compute S+A-P with P defined by relocation kind (next instruction for encoded displacement, field address for ELF relocation formula with appropriate addend). Check signed-32 fit before encoding; reject unresolved/duplicate symbols, overlapping fixups and fields outside admitted instruction ranges. Check all arithmetic before allocation or slicing. Deterministically order symbols/sections or specify stable input-order preservation; no timestamps or host paths in output.
Independent image validator parses exact bytes using bounded little-endian reads; verify ELF class, machine, type/profile, table extents, entry in file-backed executable range, load alignment/congruence, file size <= memory size, nonwrapping virtual ranges, page-rounded nonoverlap and no writable/executable page alias; reject executable stack, unsupported interpreter/dynamic segments and unapproved program headers. Validate actual permitted instruction encodings and control transfers separately; ELF structure alone does not prove code safety. Bind loader assumptions and page size to profile. Atomic publication and execute same verified bytes via immutable handle; reject substitution after validation.
Resource ledger: image bytes, symbols/fixups, segment counts, mapped bytes, alignment padding, encoding/validation work, stack and guard overhead; check preallocation, explicit numeric ceilings required before freeze. Host mapping or IO failure separate from invalid artifact and CCAM trap.
Vectors: rel32 MIN/MAX and one-over; negative displacement; duplicate/missing symbol; patch overlap; truncated headers, overflowing tables, entry in zero-fill/nonexec, W+X and page alias, invalid alignment, unsupported interpreter, tampered byte, exact quota/one-over and reproducible order. Proof: encoding/decoding correspondence, relocation equation, bounded layout and load relation; instruction semantics and ABI simulation remain E01.

## I07 — trace and certificate boundary
Input: canonical validated CCAM and exact pre/post pass representations, versioned pass identifiers, compiler identity, source manifest, semantic and target profiles, policy and budgets, I06 exact artifact bytes and validator identity. Output: accepted certificate binding all fields or explicit rejected/unknown/timeout/over-budget result; latter never certifies. Hints are untrusted. Use versioned domain-separated SHA-256 digests with unambiguous length framing; canonical encoding and schema require review. Hashes bind bytes, not semantic correctness.
Each pass relation specifies preservation of full outcome, trap ordering, effect/capability traces, memory and resource charges; preserve fuel or prove explicitly approved cost relation. Noninterference requires relational assurance distinct from functional trace simulation. Independently validate reconstructed CCAM. Chain each pass output digest to next input and final lowering/object relation to executable digest; reject missing, reordered, duplicated or unknown passes unless explicitly permitted by versioned policy. No optional SSA freeze until prototype/proof interface reviewed, per RFC §3.4.
Validator uses explicit finite parse/work/allocation/recursion limits and external deadline; limits are separate from guest fuel. Reject malformed or noncanonical encoding, policy/version mismatch, unsupported axioms or unproved relation, invalid proof, timeout and resource exhaustion. A fallback may start a new independently validated unoptimised compilation with distinct trace; never certify rejected transformed bytes. Keep counterexamples bounded and redact secrets; do not expose private source data in logs.
TCB inventory: parser/canonicalizer, hash implementation, checker/kernel, formal semantics and soundness theorem, byte-level validator, loader/OS and hardware assumptions. Compiler producer not trusted solely because it emits a certificate. Approval authenticates policy and provenance separately from proof validity; signing and trust-root policy require review.
Vectors: pass omission/reorder; exact input/output/target/policy/budget/validator substitution; certificate bit mutation; valid proof for different bytes; duplicate fields; stale version; resource ceiling, timeout and unknown; invalid trap removal, effect reorder and fuel change; independently verify fallback trace.
Freeze requires exact schemas, numeric bounds, target/loader profile and producer/consumer approvals. No executable tests, formal proof or normative change performed in this design pass.
